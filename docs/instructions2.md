Before implementing the final UI, create the asset architecture and asset manifest first.

Do not generate or invent visual assets.

Assume that the visual assets will be supplied progressively into:

/docs/presentation_elements

Build the code so that assets can be dropped into these folders later without requiring widget rewrites.

Use the exact semantic filenames specified in the project brief.

Once the architecture is ready, implement the first functional version using placeholders only where assets are missing.

Then wait for the real visual assets to be supplied and replace the placeholders without changing the interaction architecture.
